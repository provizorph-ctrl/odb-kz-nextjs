## 1. Форма входа в админку (/admin/login)

### 1.1 Позитивные тесты
- [ ] Валидный email + валидный пароль → успешный вход
- [ ] Email с заглавными буквами → вход успешен (case-insensitive)
- [ ] Пароль с пробелами в начале/конце → обрезается

### 1.2 Негативные тесты
- [ ] Пустой email → сообщение об ошибке
- [ ] Пустой пароль → сообщение об ошибке
- [ ] Невалидный email (без @) → валидация на клиенте
- [ ] Неверный пароль → сообщение "Неверный email или пароль"
- [ ] Несуществующий email → сообщение "Неверный email или пароль"
- [ ] SQL инъекция в email: `' OR 1=1 --` → не проходит
- [ ] XSS в email: `<script>alert(1)</script>` → экранируется

### 1.3 граничные значения
- [ ] Email 1 символ → валидация
- [ ] Email 255 символов → валидация
- [ ] Пароль 1 символ → валидация
- [ ] Пароль 100 символов → работает

### 1.4 Поведение
- [ ] Enter сабмитит форму
- [ ] Кнопка "Войти" сабмитит форму
- [ ] Двойной клик не отправляет форму дважды
- [ ] После успешного входа пароль не отображается в URL

## 2. Форма создания новости (/admin/news/new)

### 2.1 Позитивные тесты
- [ ] Все обязательные поля заполнены → создание успешно
- [ ] Slug уникальный → создание успешно
- [ ] Контент с HTML тегами → сохраняется корректно
- [ ] Дата по умолчанию → текущая дата

### 2.2 Валидация полей
| Поле | Тип | Мин | Макс | Обязательно | Валидация |
|------|-----|-----|------|-------------|-----------|
| slug | text | 3 | 100 | Да | a-z, 0-9, - |
| title | text | 1 | 255 | Да | Любые символы |
| content | textarea | 1 | ∞ | Да | HTML разрешён |
| description | text | 0 | 500 | Нет | — |
| isPublished | checkbox | — | — | Нет | boolean |
| isFeatured | checkbox | — | — | Нет | boolean |

### 2.3 Негативные тесты
- [ ] Пустой slug → ошибка
- [ ] Slug с пробелами → ошибка или замена на -
- [ ] Slug дубликат → ошибка (если unique constraint)
- [ ] Пустой title → ошибка
- [ ] Пустой content → ошибка
- [ ] XSS в title: `<script>alert(1)</script>` → экранируется
- [ ] SQL инъекция в slug → не проходит

### 2.4 Поведение
- [ ] Кнопка "Отмена" → возврат к списку без сохранения
- [ ] Двойной клик "Сохранить" → одна запись в БД
- [ ] Данные не теряются при ошибке валидации
